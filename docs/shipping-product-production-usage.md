## 日常操作

### 规格型号与收货资料

- 产品原“供应商”字段在页面中显示为“规格型号”；原值直接保留，`model` 原型号字段不受影响。新建发货时保存规格快照，之后修改产品不会改写已保存快照。
- 升级前没有规格快照的历史发货会读取产品当前规格，并明确标注“当前规格，历史未保存”；历史快照确实为空字符串时仍按已保存空值显示，不回退到当前规格。
- 客户页的“收货人”和“收货人联系方式”是默认收货资料，与业务联系人、业务电话分开保存。收货人和收货联系方式各最长 100 个字符。
- 客户改名会在同一事务中同步产品、订单、组装批次和已归类生产跟进。生产工序、附件、产品关联和“未归类”记录保持不变。已生成送货单仍显示当时的客户名称和收货快照。

### 普通与组装发货

1. 在“发货”页选择普通或组装发货。普通发货可同时选不同客户的订单，系统会按客户分组生成送货单。
2. 收货资料默认来自客户资料。本次覆盖只保存到送货单快照，不修改客户主资料；资料不全时可保存，结果页会提示。
3. 组装发货以 BOM 明细开始，可删除本次不发的配件，或在当前客户范围搜索并追加产品。修改套数会保留手工发货数量；“重新按 BOM 计算”只重算 BOM 行，临时追加行不乘套数。
   同一配件同时分配到订单和无订单数量时，送货单会同时显示已关联订单号和“未关联订单（数量）”；全部无订单时仍显示原有“未关联订单”。
4. 无订单或库存不足会在预览中显示警告，保存前需明确确认。服务端会重新校验客户、产品、数量、订单分配、库存和预览凭证，不信任浏览器传入的名称、规格或来源类型。
5. 保存成功后进入“发货结果与送货单”，可反复下载 PDF。下载失败不代表发货失败，应在原结果页重试，不要重新发货。来源被删除或改为其他客户后，原送货单显示失效并拒绝导出。

### 新界面操作去重与旧客户端兼容

新发货页每次加载都携带 `operation_token`。同一操作人使用同一 token 重放完全相同的表单和附件时，返回原操作结果，不重复扣库存、保存文件或生成送货单；同一 token 如被其他用户或其他内容重用，服务端拒绝。

未携带 token 的旧提交仍可保存，服务端会为当次请求生成新 token；这种兼容路径不能保证跨请求去重。`operation_token` 是发货意图去重标识，不是 CSRF token。

保留的旧发货计划批准接口也使用同一结果收据和去重规则：摘要绑定计划 ID、本次明细、附件及收货覆盖；成功后进入送货单结果页，并按订单实际客户分组。相同 token 的完全相同请求会在计划状态等可变检查前返回原结果。

### 历史发货按现价补齐

- 这项操作记录的是“当前产品含税价”，它可能与当时成交价不同；确认前必须核对，不要将本功能当作恢复历史成交价。
- 在已发货列表先设置搜索、客户和日期筛选，再选择“按现价批量补齐缺价（预览）”。功能同时要求发货管理和价格查看权限。
- 预览显示可补和跳过数量及原因。只补 `NULL` 价格；已保存价格（包括 0）、无当前价、财务或对账占用的来源都保持不变。不混合货币，不做汇率换算。
- 预览 token 绑定当前操作人、筛选条件、明确来源集和状态，15 分钟后失效。确认 POST 会重新校验，价格或占用状态变化时整批拒绝。成功后单独写入补价审计，不混入结构升级。

### 生产跟进客户归类

- 客户和关键词是“且”关系；“未归类”只匹配旧的空客户记录。新建时可在当前客户内搜索产品，也可保留手工输入方式；产品 ID、图号、名称或客户矛盾时拒绝。
- 切换客户会立即清除已选产品关联，搜索有防抖并会取消旧请求，防止上一客户的候选项混入。工序完成或撤销后保留客户与关键词筛选。

## 权限、CSRF 和价格隔离

- 已有生产跟进主表单创建路径保持“登录即可”的旧策略，没有在本次扩大或收紧。新增的客户内产品查找和归类写入、以及原工序管理操作，要求生产跟进管理权限；归类 POST 需要会话 CSRF token。
- 生产归类 CSRF token 按 UTF-8 字节做恒定时间比较；无效中文 token 与其他无效 token 一样返回 403，不产生写入。
- 批量补价的预览和执行都是有 CSRF 保护的 POST，并要求发货管理与价格查看权限。组装预览、组装保存、配件查找与送货单读取使用原发货会话和权限模型；不把发货去重 token 说成 CSRF 保护。
- 无价格权限用户的已发货页面不查询、不显示单价和金额；配件搜索及生产产品 JSON 只返回 ID、图号、名称和规格。已发货 Excel 本身无价格列，新送货单 PDF 不包含价格。结果页和 PDF 地址都需要发货查看权限，未登录直接访问会转到登录页。
