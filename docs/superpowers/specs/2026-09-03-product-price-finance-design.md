# 产品双页资料、价格权限与财务开票设计

## 背景与目标

当前每个产品的基本属性、图纸附件、材料、作业指导书和检验要求集中在同一个详情与编辑页面；客户资料只保存联系人、地址、邮箱和电话；发货记录没有价格快照，也没有可追溯的开票与收款流程。

本次功能在不改变“组装件图号只是配件属性”的前提下，实现以下目标：

- 每个产品仍是一条产品记录，但查看和编辑均分为“基本信息”和“技术资料”两个页签。
- 产品保存一个当前单价和币种，价格只对管理员或被授权人员可见。
- 普通发货和组装件发货保存发货当时的产品价格快照，后续调价不改变历史金额。
- 客户资料保存结构化开票信息，财务开票单直接关联实际发货明细。
- 同一客户的多条发货记录可合并开票，形成“待开票、已开票、已收款”的可审计流程。
- 普通送货单继续不显示价格；财务人员使用独立的含价 Excel/PDF 清单。

## 范围

### 包含

- 产品查看页和编辑页的双页签结构。
- 产品当前单价、币种及价格权限。
- 普通发货记录与组装发货配件明细的价格快照、行金额和汇总金额。
- 历史发货价格的受控补录。
- 客户结构化开票信息及独立编辑入口。
- 独立财务开票模块、合并开票、收款登记和作废流程。
- 财务 Excel/PDF 导出。
- 数据迁移、权限隔离、服务端校验和自动化测试。

### 不包含

- 将组装件图号创建为产品或给组装件设置独立价格。
- 产品价格历史版本、生效日期或多套报价。
- 一条发货明细的部分开票。
- 一张发票的分次收款、账龄分析、总账、应付或会计凭证。
- 在普通送货单 PDF 中显示价格。
- 用当前产品价格自动回填既有历史发货。

## 产品页面结构

### 基本信息页签

基本信息包含现有产品身份和经营属性：

- 产品图号、产品名称。
- 客户、供应商。
- 包装数量、SKU、条码及现有库存相关属性。
- 产品所属的一个或多个组装件图号及每套配件用量。
- 当前单价和币种；该区域仅向有价格查看权限的用户返回和显示。
- 现有备注、更新时间及审计信息。

### 技术资料页签

技术资料包含：

- 图纸和其他产品附件。
- 材料信息。
- 作业指导书。
- 检验要求。

查看和编辑均使用相同的两个页签语义。两个页签操作同一 `manuals` 产品记录，不复制产品，也不创建子产品。

现有产品详情地址继续有效，默认进入“基本信息”；增加稳定的“技术资料”地址。页面间切换保留当前产品 ID。未经登录或没有价格权限的访问者只能得到非价格字段，价格不能先进入 HTML、JSON 或脚本变量后再靠 CSS 隐藏。

## 产品价格规则

每个产品只维护一个当前价格：

- `unit_price_minor`：以最小货币单位保存的整数金额；空值表示“未设置价格”，`0` 是合法价格。
- `currency`：标准三字母币种代码，默认 `CNY`；首期支持 `CNY`、`USD`、`EUR`、`HKD`、`GBP` 和 `JPY`。
- 金额输入使用十进制解析，拒绝负数、超出该币种精度的值和非法币种；不得通过二进制浮点数计算或落库。
- 修改当前价格只影响之后新建的发货价格快照。

产品价格编辑要求同时具备价格查看权限和现有产品编辑权限。只具备价格查看权限的人员可以查看，但不能修改。

## 发货价格快照

### 普通发货

普通发货保存：

- 发货时的单位价格最小单位值。
- 发货时的币种。
- 发货数量。
- 行总价，定义为 `单位价格 × 发货数量`。

### 组装件发货

组装件本身不是产品，因此不保存或计算独立单价。每条 `assembly_shipment_items` 配件明细分别保存该配件发货时的单位价格和币种；批次总价为配件明细行金额之和。

如果同一组装发货批次意外包含不同币种，只能按币种分别汇总和开票，不能把不同币种直接相加成一个总价。

### 历史稳定性

- 产品当前价格变化不更新任何已有发货价格快照。
- 未加入开票单的发货记录修改数量时，使用该记录自己的单位价格快照重新计算行金额，不重新读取产品当前价格。
- 发货记录加入开票单后，发货日期、产品、数量、单位价格和币种全部锁定；不影响金额的物流备注仍可维护。
- 已被开票单引用的发货记录不能直接删除；必须先从待开票单移除，或按规则作废正式开票单。
- 服务端根据单位价格快照和数量计算总价，不信任浏览器提交的行金额或合计金额。

## 历史价格补录

数据库升级后，已有发货记录的价格快照保持空值并显示“未记录价格”，不自动套用产品当前价格。

历史价格补录要求操作者同时具备价格查看权限和发货管理权限。补录保存明确的单位价格、币种、操作人和操作时间。已经加入开票单的记录不允许补录或改价。

没有价格的产品仍允许下单和发货，以避免中断现有生产流程；对应发货记录显示“价格未设置”，补齐价格快照前不能加入财务开票单。

## 客户开票资料

`customers` 增加以下字段：

- 开票抬头。
- 统一社会信用代码／税号。
- 注册地址。
- 注册电话。
- 开户银行。
- 银行账号。
- 收票邮箱。

原有联系人、业务地址、邮箱、电话和备注继续保留。客户列表提供独立“开票信息”入口和表单，避免把主列表横向扩展得过宽。

客户管理权限可以维护开票资料；财务管理权限可以读取开票资料用于开票，但不因此获得修改客户基本资料的权限。

已被财务开票单关联的客户不能物理删除。客户后续改名或修改开票资料只影响新生成的开票单，不改写历史开票资料快照。

## 财务开票模型

### 开票单

独立的开票单表保存：

- 客户 ID，以及开票时的客户名称快照。
- 开票抬头、税号、注册地址、注册电话、开户银行、银行账号和收票邮箱快照。
- 币种和服务器计算的总金额；本期不区分含税价与未税价。
- 状态：`pending`（待开票）、`invoiced`（已开票）、`paid`（已收款）、`void`（已作废）。
- 发票号码、开票日期、收款日期和财务备注。
- 创建人、更新人、创建时间和更新时间。

开票单只能包含一个客户和一种币种。客户或币种不同的发货记录必须分别建单。

### 开票明细

每条开票明细关联一个完整的发货来源：

- 普通发货记录；或
- 组装发货中的一个配件明细。

明细保存来源类型、来源 ID、产品图号、产品名称、数量、单位价格、币种和行金额快照。开票单因此可以组合普通发货和组装发货明细，但不能把同一来源重复用于两个有效开票单。

组装发货在财务中按配件明细计价，同时显示所属客户、组装图号和组装批次，便于追溯。一个组装批次可按币种拆到不同开票单，但同一配件明细不可拆分数量。

## 财务业务流程

1. 财务人员选择客户。
2. 系统列出该客户尚未开票且已记录价格的普通发货与组装发货配件明细。
3. 财务人员勾选同一币种的多条明细，服务器再次验证客户、币种、价格状态和占用状态。
4. 系统创建“待开票”单，并保存客户开票资料和发货金额快照。
5. 待开票阶段可以增加或移除尚未被其他开票单占用的明细。
6. 填写发票号码和开票日期后转为“已开票”；明细和金额随即锁定。
7. 填写收款日期后转为“已收款”。本期一次性视为全额收款，不记录多次收款明细。

正式开票后不能直接删除。需要纠错时：

- `invoiced` 可以作废；作废保留完整历史、操作者和时间，并释放其发货明细以便重新开票。
- `paid` 必须先撤销收款状态回到 `invoiced`，再执行作废。
- 待开票单可以删除；删除后释放其发货明细。

数据库层使用有效占用标记和唯一约束，配合事务内复查，防止并发操作把同一发货明细加入多个有效开票单。

## 页面与导出

### 已发清单

有价格权限时显示：

- 单价。
- 币种。
- 行总价。
- 价格状态。
- 关联开票单和财务状态。

组装发货卡片显示各配件价格与按币种汇总的批次金额。无价格权限时不查询、不序列化、不渲染上述字段。

### 财务模块

财务页面包括：

- 待开票发货明细筛选与选择。
- 开票单列表和客户、日期、状态、发票号码筛选。
- 开票单详情、开票登记、收款登记、撤销收款和作废操作。
- 含价 Excel/PDF 财务清单导出。

财务导出包含客户开票资料、发票信息、发货日期、订单号或组装批次、产品图号、产品名称、数量、单价、币种、行金额和总金额。

现有普通送货单 PDF、客户签收页面和公开签收链接继续不显示任何价格。

## 权限模型

新增两个用户权限：

- `price_view`：查看产品当前价格、发货价格快照和金额。
- `finance_manage`：进入财务模块、查看客户开票资料、创建和管理开票单；此权限在价格相关页面中隐含 `price_view`。

管理员始终拥有全部权限。具体操作还需与现有权限组合：

| 操作 | 权限要求 |
| --- | --- |
| 查看产品或发货价格 | `price_view` 或 `finance_manage` |
| 修改产品当前价格 | 上述价格权限 + `product_edit` |
| 补录历史发货价格 | 上述价格权限 + `shipped_manage` |
| 维护客户开票资料 | `customers` |
| 读取客户开票资料并管理开票单 | `finance_manage` |

所有后端详情、列表、搜索、导出和 JSON 接口独立执行权限检查。模板条件渲染不能代替后端字段隔离。

## 数据模型变更

### 现有表新增字段

- `manuals`：`unit_price_minor`、`currency`。
- `product_order_shipments`：单位价格快照、币种、价格补录审计字段。
- `assembly_shipment_items`：单位价格快照、币种、价格补录审计字段。
- `customers`：七项开票资料字段。
- `users`：价格查看权限和财务管理权限字段。

行总价一般由快照价格与数量计算，不作为可由客户端修改的独立事实。开票单与开票明细保存最终金额快照，以固定正式财务记录。

### 新表

- `finance_invoices`：开票单、客户与开票资料快照、币种、总额、状态及审计信息。
- `finance_invoice_items`：发货来源、产品与金额快照、有效占用标记及审计信息。

迁移采用现有启动时幂等 `ensure_*` 风格，仅增加字段、表和索引，不覆盖既有数据。新权限对管理员默认开启，对既有普通用户默认关闭，避免升级后意外暴露价格。

## 事务与并发

创建或调整待开票单在单个 SQLite 写事务中完成：

1. 重新读取全部发货来源。
2. 验证客户一致、币种一致、价格存在、发货记录未被占用。
3. 锁定或建立来源的有效占用记录。
4. 从服务端价格快照和数量计算每行金额与总额。
5. 保存开票单、明细和审计信息。

状态转换、作废和释放明细同样在单一事务内完成。任何校验或写入失败均整体回滚。

## 校验与错误处理

核心规则和提示包括：

- “产品价格不能为负数”。
- “价格格式或币种不正确”。
- “该发货记录尚未记录价格，不能开票”。
- “只能合并同一客户、同一币种的发货记录”。
- “该发货记录已加入其他开票单”。
- “已开票记录不能修改发货数量或价格”。
- “请填写发票号码和开票日期”。
- “已收款记录需先撤销收款后才能作废”。
- “该客户已有财务记录，不能删除”。

页面提交的客户名称、币种、价格、金额、状态和来源归属均由服务器重新读取和验证；所有 SQL 值使用参数绑定。

## 测试与验收

### 产品页面

- 原产品链接默认进入基本信息页签，技术资料页签可稳定访问。
- 两个编辑页签保存后仍指向同一产品记录。
- 图纸、材料、作业指导书和检验要求完整迁移到技术资料页签。

### 价格与权限

- 管理员、有价格权限、无价格权限三类账号分别验证页面、JSON、导出和直接 URL。
- 无权限响应中不存在价格和总价值，不只是界面隐藏。
- 当前价格修改不改变既有发货快照。
- `0`、空值、非法小数、负数和币种校验正确。

### 发货与组装

- 普通发货和组装配件明细均在创建时保存正确价格快照。
- 组装批次按币种正确汇总，不能跨币种错误相加。
- 未开票发货改数量按原快照重算；开票后修改和删除被阻止。
- 历史发货保持空价格，授权补录后才可开票。

### 客户与财务

- 客户开票资料增删改查及权限检查正确。
- 开票单保存客户开票资料快照；修改客户后历史开票单不变。
- 同一客户同一币种多条发货可合并，跨客户、跨币种和重复来源被拒绝。
- 待开票、已开票、已收款、撤销收款和作废状态转换符合规则。
- 并发创建开票单时，同一发货来源最多被一个有效开票单占用。
- Excel/PDF 财务清单金额和字段正确，普通送货单与客户签收页面始终不含价格。

## 验收标准

- 用户能在产品的基本信息与技术资料两个页签中完成现有查看和编辑工作。
- 未授权用户无法通过任何页面、接口或导出获得产品或发货价格。
- 每次普通或组装发货形成稳定价格快照，历史金额不随产品调价变化。
- 客户开票资料能够直接用于创建开票单，并以快照方式保留历史。
- 财务人员可把同一客户、同一币种的多条发货明细合并开票并登记收款。
- 无价格记录、重复开票、跨客户／跨币种、已开票后修改等异常均被服务器明确阻止。
