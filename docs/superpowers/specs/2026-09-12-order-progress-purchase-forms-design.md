# 五项业务页面调整设计

日期：2026-09-12

状态：用户已确认，进入本地实施与验证；不修改线上业务数据或服务。

基线：`codex/shared-products` 的 `f54b327`，应用代码与最近 VPS 发布一致。

## 1. 范围与已确认事项

本轮仅包含：

1. 发货选择客户后带入收货人、收货电话和地址。
2. 生产订单先显示组装订单或普通订单汇总，再进入明细。
3. 生产跟进按订单进入明细，在明细中填写各工艺完成数量、进度和备注。
4. 原材料采购页面与 Excel 导出按用户提供的采购订单模板设计。
5. 纸箱和外协采购使用同一订单式布局，保留各自字段。

用户已同意按每道工艺的“已完成数量 / 订单需求数量”计算进度，例如 80 / 200 = 40%。
本轮先本地实施与验证，不部署 NAS/VPS，不发送邮件，不补写实际客户资料，不创建真实采购或生产订单。

## 2. 方案选择

采用“现有订单明细上增加汇总展示，工艺卡明确关联订单明细”的方式。

- 推荐方案保留 `product_orders.id`，不重建发货、库存、财务的关联；增加的生产关联只服务于工艺跟进。
- 仅折叠现有列表改动小，但工艺卡仍只对应产品，无法区分不同订单的进度，不满足本次要求。
- 另建完整生产单系统可支持拆批排产，但会引入重复录入和新的单据生命周期，超出本轮范围。

实现分为三个可独立测试的单元：收货默认资料、订单汇总与工艺跟进、采购表单与导出。
业务查询和数量校验放在小型领域模块中，路由负责权限与请求处理，模板负责展示，避免继续把全部逻辑堆入 `app.py`。

## 3. 发货收货资料

### 已核实的原因

2026-09-12 只读查询 VPS 客户记录：宁波知了智能科技有限公司的 `contact`、`phone`、`address` 非空，`recipient_name`、`recipient_phone` 都为空。
现有 `shipment_operations` 仅将专用收货字段传给页面；组装发货的客户切换处理直接使用这些值，因此姓名和电话显示为空。
该诊断不涉及修改线上数据，也不将实际联系方式写入本设计。

### 默认规则

- 优先使用客户档案的专用收货人和收货电话。
- 两个专用字段都为空时，使用联系人和联系电话作为本次默认资料，页面注明“来自客户联系人，请核对”。
- 如果只填写了一个专用字段，不把另一位联系人的资料混入；缺失项提示补充。
- 地址使用客户收货地址；缺失时保持为空并提示，不从无关客户或历史单据推断。
- 按订单和按组装件发货使用同一默认规则。多客户订单按客户分别处理，不能串用资料。
- 切换客户重新带入对应默认值；修改套数、刷新配件预览不能覆盖用户手工修改的收货资料。
- 服务端解析与页面规则保持一致；明确提交的空值仍代表本次留空，不能被默认值重新覆盖。
- 保存到本次送货单快照，不回写客户档案，不追改历史送货单。Excel/PDF/邮件附件继续读取单据快照。

## 4. 生产订单汇总与明细

- 生产订单默认页显示：客户、订单号、类型、组装图号或普通订单产品概况、套数（组装订单）、产品项数、下单日期、交货期、发货状态、查看明细。
- 汇总分组使用完整的客户、订单号、下单日期、组装图号和组装套数。不同客户、不同组装号、不同套数不能仅因订单号相同而合并展示。
- 普通订单不要求组装号；一张普通订单内有多个产品时显示产品项数，进入明细查看。
- 组装套数是订单级展示值，不能把每个配件行重复存储的套数相加。
- 交货期不同时显示起止范围；全部明细发完才显示已发完。不同单位的产品数量不作为一个“总件数”相加。
- 这是展示分组，不合并、删除或重新编号任何原始订单明细；同组多次录入的产品行仍分别保留。
- 详情链接以实际明细 ID 为入口，由服务端重新解析其组；找不到记录返回明确提示。不能信任客户端传入的客户或组装号来决定可更新的行。
- 保留客户、关键词、状态/排序等现有筛选能力。关键词命中一个产品时，返回包含该产品的订单汇总；进入详情显示该订单组的全部明细，避免只看到命中行。
- 明细保留原有图号、名称、规格型号、需求数量、交货期、库存/入库、发货、备注及编辑等操作。操作后返回当前明细或原筛选结果，不跳到后台首页。
- 不在本轮增加整组删除、整组改数量或新排产功能。

## 5. 按订单生产跟进

### 导航和关联

- 生产跟进默认显示与生产订单一致的订单汇总，并支持客户、订单号、组装号、产品图号和名称查询。
- 点击订单后显示每条产品明细：图号、名称、规格、需求数量，以及该明细的工艺、完成数量、进度、备注和工艺卡入口。
- 在 `production_followups` 增加可空 `order_id`，唯一约束只覆盖非空值：每条订单明细本轮最多一张订单工艺卡。
- 通过显式 POST 操作开始跟进并创建工艺快照；只打开页面不产生工艺卡。重复点击或并发提交返回同一张卡，不重复创建。
- 创建卡时从服务端订单行取得产品、客户和日期，复制该产品当前工艺配置及备注。后续修改产品工艺模板不覆盖已开始的订单工艺。
- 原有未关联订单的工艺卡在“历史／独立工艺卡”入口完整保留，包括附件、备注、完成时间和现有操作；不根据同名产品自动绑定某张订单，也不把旧完成状态猜测成件数。

### 完成数量与进度

- 在订单工艺步骤增加累计完成数量，初始 0。输入的是当前累计数，不是“再增加多少”，重复保存相同值不会重复累加。
- 每步数量必须为整数，范围为 0 至该订单明细需求数量；前后端都校验。保存需校验工艺确实属于目标订单明细。
- 每步进度 = 累计完成数量 / 当前订单需求数量，显示数量与百分比。0 为未开始，中间值为进行中，达到需求数为已完成。
- 各工艺独立填写，不强制上一道完成才允许下一道，以兼容分批和并行作业。
- “全部完成”快捷操作把该步数量设为订单需求数；撤回需明确确认后归零。完成时间与完成人随状态变化保持一致。
- 每次数量修改记录操作者、时间、修改前后数量；提交携带版本信息，过期页面提示刷新，不静默覆盖他人的修改。
- 保留工艺增删、排序和备注。删除已有完成数量的工艺需额外确认，数量变更历史保留；删改工艺之后按当前有效工艺重算展示。
- 产品明细可显示综合工艺进度：各有效工艺累计完成数之和 /（需求数量 × 有效工艺数），明确标注为“工艺进度”，不将其当成成品数量或库存。无工艺时显示“未配置工艺”，不是 100%。
- 不自动入库、不自动发货、不据此修改库存余额。

### 订单变更保护

- 工艺已关联的订单明细不能直接改成另一个产品或删除，界面给出原因。仅从未记录过完成数量的订单工艺卡允许确认删除后解除关联；已有数量变更历史的订单工艺卡禁止删除，不能通过先归零规避。沿用既有财务、库存、发货删除保护。
- 订单需求数量不能改小到任何一道工艺已完成数量以下；可增加需求数量，进度按新需求数重新计算，旧完成数量和审计记录不变。
- 增量更新后曾经完成但不再满足新需求数的工艺回到进行中，历史完成记录仍可追溯。
- 所有订单数量修改入口和工艺数量保存入口均使用事务内的当前数据验证，避免并发下突破数量限制。

## 6. 原材料采购表单与 Excel

参考文件：`/Users/derek/Desktop/原材料采购模板.xlsx`，工作表“采购订单”。
模板的 `A3:J5` 为供应商信息，`A7:J16` 为材料表，`A18:J24` 为收货信息、要求、日期和签字信息。只使用布局和字段，不把模板中的示例供应商、产品或数量导入系统。

### 页面

- 页面采用订单式结构：公司标题 → 供应商及单号 → 材料明细 → 收货资料和要求 → 日期/经办人 → 保存与导出。
- 选择供应商后立即显示供应商名称、代码、联系人、电话、地址，邮箱作为补充资料展示。切换供应商立即更新且不残留上一家资料。
- 供应商资料来自服务端选择记录，不信任表单伪造的供应商名称或电话。默认只读，资料维护仍在供应商管理中完成。
- 已有订单展示保存时的供应商快照；未更换供应商时不能因为打开编辑页面就悄悄刷新成新的档案资料。
- 原材料明细列按模板排列：物品名称、材质、长 mm、宽 mm、厚度 mm、表面、数量、单位、预计到货日期、备注。保留新增、删行、排序和错误后回显。
- 常用收货资料继续从现有收货模板读取，可在本单修改；供应商地址与本公司收货地址严格区分。
- 经办人默认当前操作用户，历史单据沿用已有创建者；下单日期使用日期选择框且必填，不使用模板中的固定日期。

### 导出

- Excel 与订单页字段顺序一致，采用模板的分区、边框、合并单元格和签字位置。
- 横向 A4，完整打印公司标题、全部明细和收货/签字区域；模板原始打印区域从第 2 行开始，本次导出改为包含第 1 行公司标题。
- 单页宽度适配 A4，明细可纵向分页，重复表头；不强行把长订单缩成一页，不截断备注和地址。
- 数量和尺寸保留数值，日期保留日期格式，名称/编码等文本不能变成公式；供应商编号、电话等保留前导零。
- 现有原材料导出遗漏物品名称和单位，本次按模板补齐。已有 PDF 导出入口保留并至少保证字段完整；本轮不将采购 PDF 另行扩展为新的排版项目。
- 模板尾部常用要求映射到现有订单备注/收货模板配置，不批量覆盖线上设置，不固定写入示例人员或联系方式。

## 7. 纸箱与外协采购

- 复用上节的订单页顶栏、供应商自动显示、收货资料、日期、签字和 Excel 打印规则。
- 纸箱保留物品名称、材质、长宽高、尺寸说明/历史尺寸、数量、单位、单价、合计、到货日期和备注。
- 外协保留物品/图号、材质、尺寸、厚度、表面、数量、单位、单价、合计、到货日期和备注。
- 空单价仍为未录价，不自动当作免费；数量和金额计算沿用现有精度与验证。
- 金额列严格沿用采购价格权限：无权用户的页面数据、接口和导出都不含隐藏价格，不能只靠 CSS 隐藏。
- 不改变其他采购类别的业务规则，不丢失从旧纸箱采购迁移来的尺寸或来源信息。
- 到货、批量入库、采购库存和出库继续引用原采购明细 ID；表格换样式不影响这些关系。
