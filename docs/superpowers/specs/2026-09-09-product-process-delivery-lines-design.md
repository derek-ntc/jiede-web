# 产品批量维护、可配置工艺与送货明细设计

## 目标

本次升级解决四类实际操作问题：

1. Excel 产品导入中的“规格型号”没有写入产品列表的规格型号字段。
2. 产品只能逐条删除，而且删除后跳回后台管理首页。
3. 生产工艺固定为激光、折弯、焊接，不能按产品维护或按工艺卡调整。
4. 发货明细不能保留 0 数量行，追加产品和逐行备注也不能完整进入送货单。

升级后，产品导入和删除仍留在产品列表工作流中；产品可维护默认工艺模板，生产跟进保存独立工艺快照；按订单和按组装件发货均可形成一组可编辑送货明细，0 数量行只进入送货单，正数行继续进入库存、订单和财务流程。

## 非目标

- 不删除历史生产跟进中的 `laser_completed_at`、`bending_completed_at`、`welding_completed_at` 字段。
- 不重写历史发货价格、开票、对账或签收数据。
- 不允许 0 数量改变库存、订单已发数量或财务金额。
- 不改变产品价格查看权限、发货权限及生产跟进权限的含义。
- 本阶段不部署 VPS/NAS，不操作正式数据库。

## 现状与根因

### Excel 规格型号

当前导入器将 Excel 表头“规格型号”解析为 `manuals.drawing_no`，用于产品匹配；`apply_product_bom_import` 的新增和更新语句都没有写入 `manuals.supplier`。产品列表已将 `supplier` 显示为“规格型号”，所以导入成功后该列仍为空。导入页甚至明确提示该列不会写入产品属性，行为与现在的业务称谓不一致。

### 产品删除

产品列表已有勾选框，但只用于批量设置组装属性。单条删除完成后固定跳转 `admin_index`，没有携带产品列表的查询、客户、规格型号及排序状态，也没有批量删除端点。

### 生产工艺

生产跟进把激光、折弯、焊接固化成三列和三个固定操作。工艺卡也固定循环这三项，无法表达不同产品的工艺路线。

### 发货和送货单

组装发货已经允许删除 BOM 配件和临时追加同客户产品，但实际数量使用正整数校验，0 会被拒绝。按订单发货只能增加订单行。送货单在查看时从发货来源动态重建明细，没有独立的逐行快照，因此无法可靠保留 0 数量行和本次备注。

## 设计总览

本次采用三层数据边界：

- 产品层保存当前主数据和默认工艺模板。
- 生产跟进层在创建时复制工艺模板，后续独立维护，保证历史稳定。
- 发货层保存真正影响订单、库存和财务的正数记录；送货单层保存本次提交的完整行快照，包括 0 数量和备注。

任何展示在送货单上的行都进入送货单快照；只有数量大于 0 的行才允许生成发货来源、库存流水及财务来源。

## 产品 Excel 导入

### 字段规则

现有 `.xls`、`.xlsx`、`.xlsm` 模板保持兼容，不增加新的必填列。Excel 中的“规格型号”继续作为产品图号进行客户内匹配，同时也作为本次导入的产品规格型号：

- 新增产品：同时写入 `manuals.drawing_no` 与 `manuals.supplier`。
- 匹配已有产品：更新 `product_name`、`sku`、`unit` 和 `supplier`；图纸、价格、备注、材料及组装关系仍按现有规则保留。
- 相同产品在多个组装件区块出现时，“规格型号”必须一致，否则预览报错且不能导入。

导入预览增加“规格型号”列；导入说明改为“规格型号同时用于产品图号匹配并写入产品规格型号”。下载模板维持当前列顺序。

## 产品删除

### 界面

沿用产品列表现有勾选框。在批量设置组装属性工具栏增加红色“批量删除”按钮。按钮在未选择产品时禁用；点击后打开模态确认框，按当前选择顺序显示：

- 产品图号
- 产品名称
- 客户
- 规格型号

确认框显示总数，只有点击红色“确认删除”才提交；取消或关闭不产生请求。无 JavaScript 时批量删除按钮不直接提交，避免绕过清单确认。

### 服务端规则

新增产品批量删除 POST 端点，继续要求 `product_edit` 权限。端点去重并验证全部 ID，先加载全部产品并对每个产品执行现有财务和对账可变性检查，再开始删除：

- 任一 ID 无效、任一产品受财务/对账锁定时，整批回滚，一个也不删除。
- 删除范围与单删一致：产品材料、组装关系、产品文件记录及产品主记录。待删除上传文件先原子移动到本次操作的隔离暂存目录；数据库失败时移回原位，数据库提交后再清理暂存文件。最终清理失败只留下不可访问的隔离文件并记录错误，不造成数据库引用丢失。
- 成功消息显示删除数量；失败消息说明整批未删除及原因。

单删和批删都回到 `products_index`，并保留 `q`、`supplier`、`customer`、`sort`、`direction`。单删表单也携带这些返回参数。

## 产品默认工艺

### 数据结构

新增：

- `manual_process_configs`：每个产品一条配置状态，`manual_id` 为主键。配置行存在但没有步骤，表示业务明确设置为“无默认工艺”。
- `manual_process_steps`：`id`、`manual_id`、`name`、`sort_order`、`created_at`、`updated_at`。同一产品的工艺名称按大小写不重复。

没有配置行的历史或新产品使用兼容默认值“激光、折弯、焊接”。第一次保存技术资料中的工艺设置时创建配置行；即使删除全部工艺，也保留配置行，防止默认工艺再次出现。

产品技术资料增加“默认生产工艺”编辑区，可新增名称、删除及使用上移/下移按钮排序。名称去除首尾空格、不能为空、最长 100 个字符、同一产品不能重复。保存工艺不会改写已经创建的生产跟进。

## 生产跟进工艺快照

### 数据结构与迁移

新增 `production_followup_process_steps`：

- `id`、`followup_id`
- `name`、`sort_order`
- `completed_at`、`completed_by`
- `created_at`、`updated_at`

迁移对每条尚无步骤的历史生产跟进按顺序创建激光、折弯、焊接三项，并从旧完成时间字段复制状态。迁移使用“仅当该跟进没有任何步骤时才创建”的幂等条件，重复启动不会新增重复步骤。

创建生产跟进时：

- 已关联产品且产品有显式配置：复制该产品当前步骤，包括显式空列表。
- 产品没有显式配置或跟进未关联产品：复制兼容默认值激光、折弯、焊接。

旧三列保留用于兼容历史代码。对名称为激光、折弯、焊接的步骤完成或撤回时同步旧列；读取和工艺卡以新步骤表为准。

### 操作规则

生产跟进列表和工艺卡按 `sort_order, id` 展示步骤。具有 `production_followups_manage` 权限的用户可以：

- 在末尾新增工艺。
- 删除未完成工艺；已完成工艺必须先撤回。
- 在未完成尾部内上移或下移；已完成的前缀顺序固定。
- 只能完成当前第一项未完成工艺。
- 只能撤回最后一项已完成工艺。

完成时记录北京时间对应的持久时间和当前操作人。工艺卡继续输出两份打印联，并显示每项状态、完成时间和操作人。

## 可编辑发货明细

### 通用行模型

按订单和按组装件页面都形成同样的提交行：

- 产品 ID、产品图号、产品名称、规格型号、单位
- 来源类型（订单、BOM、临时追加）和可选订单 ID
- 计算数量、实际发货数量
- 本行备注
- 当前库存、订单匹配及警告信息

实际发货数量允许 `0` 到系统最大数量。整次操作至少有一行大于 0；全部为 0 时不创建空发货操作，并提示“至少有一个产品的发货数量必须大于 0”。

### 追加产品

两种模式的明细表底部都提供“添加产品”区域，按当前客户搜索产品图号或名称，一次可追加多个。组装模式按产品合并重复项；订单模式把同一产品呈现为一行并在后台维护多个订单分配：

- 只返回当前客户产品。
- 按订单模式保留当前一次操作可包含多个客户、并按客户生成多张送货单的能力；追加产品前必须在客户筛选框选定一个具体客户，该产品只进入该客户分组。
- 按订单模式先按交货期、订单 ID 匹配该产品的未发订单，并把正数数量分配到订单。
- 超出未发订单的部分或没有订单的产品，保存为补充发货记录，并显示“未关联订单”警告。
- 按组装件模式沿用现有 `source_kind=extra` 逻辑，每套用量和计算数量为 0，实际数量由用户填写。
- 库存不足不阻止保存；只扣除现有库存，差额记录为缺货数量并显示警告。

### 正数发货来源

现有普通订单发货和组装发货结构继续使用。为按订单模式中无法分配到订单的正数追加量新增 `supplemental_shipments`：

- `id`、`operation_id`、`manual_id`、`customer`
- 产品图号、名称、规格型号快照
- `shipped_quantity`、`inventory_deducted_quantity`、`inventory_shortage_quantity`
- 发货时间、物流备注、行备注
- 单价、货币、价格记录人/时间快照
- 创建人及时间

补充发货出现在已发货清单，允许进入财务和对账来源，删除或编辑时遵循与现有发货相同的财务/对账锁定、库存恢复和送货单失效规则。历史数据不生成补充发货记录。

为支持这一来源，`delivery_note_sources`、`finance_invoice_items` 和 `reconciliation_statement_items` 的来源类型约束增加 `supplemental`。SQLite 迁移使用“新建兼容表、复制全部旧行、校验行数与关键字段摘要、事务内替换旧表、重建索引和触发器”的方式，不就地丢弃约束；迁移前后的普通及组装来源标识保持不变。送货单来源的更新/删除触发器同时覆盖补充发货。价格补录无需为补充发货新增历史处理，因为补充发货从第一条记录起即保存价格快照。

组装发货明细新增 `remark`。普通订单发货复用现有 `product_order_shipments.remark` 保存行备注；页面原“发货备注”继续作为整次物流备注，不与行备注混用。价格权限和快照规则保持不变。

### 0 数量行

- 不创建普通、组装或补充发货的财务数量。
- 不创建库存流水，不改变订单汇总。
- 在界面标记“本次不发”。
- 仍进入本次送货单快照，数量明确显示 0，备注正常显示。

组装发货可以在 `assembly_shipment_items` 保留 0 数量行用于批次查看，但相关订单分配可以为空，扣减量和缺货量必须为 0；财务和对账查询明确排除 `shipped_quantity <= 0`。

## 送货单行快照

新增 `delivery_note_items`：

- `id`、`note_id`、`sort_order`
- `manual_id`、`source_type`、`source_id`
- 订单号、组装图号
- 产品图号、产品名称、规格型号、单位快照
- `quantity`（允许 0）和 `remark`

创建发货操作时，在同一数据库事务内先保存正数发货来源，再按用户确认的完整行顺序写入送货单明细。`delivery_note_sources` 继续关联真正的正数发货来源，供失效、编辑和删除检查使用；`delivery_note_items` 负责永久呈现本次文档内容。

新送货单优先读取快照行。历史送货单没有快照行时继续从来源动态读取，保持兼容。送货单页面、PDF和打印表格在最后增加“备注”列；0 数量行正常显示且金额语义为 0。送货单不显示产品价格。

## 一致性与失败处理

- 产品批删的数据库记录、工艺保存、工艺卡状态变化、发货来源、库存流水、发货图片、送货单和行快照都沿用应用级写锁和数据库事务；产品文件删除使用前述隔离暂存与失败恢复流程。
- 发货预览令牌和幂等操作标识覆盖产品选择、数量及行备注。重复提交相同内容返回原结果；相同标识提交不同内容返回冲突。
- 保存前重新核对订单余额、产品归属和库存；状态变化时返回最新预览，不部分保存。
- 任一正数来源、库存或送货单快照写入失败时整次回滚。图片暂存与现有原子清理规则保持一致。
- 用户输入的工艺名和备注在 HTML/PDF 中转义；工艺名最长 100 字符，发货行备注最长 500 字符。

## 权限

- Excel 导入和新增产品：沿用 `product_create`。
- 产品批量删除及默认工艺维护：`product_edit`。
- 生产跟进工艺增删、排序、完成和撤回：`production_followups_manage`。
- 发货行调整、追加产品、备注和保存：`shipped_manage`。
- 查看工艺卡、已发货记录和送货单：沿用现有查看权限。
- 无价格查看权限的用户在新增行、警告、送货单及确认界面中仍看不到价格。

## 测试与验收

按测试驱动方式逐项实施，至少覆盖：

1. Excel 新增及匹配已有产品时写入规格型号，同时保留价格、图纸、备注和既有组装关系。
2. 批删确认数据、无选择、重复/无效 ID、权限拒绝、财务/对账锁定整批回滚、文件清理及筛选返回。
3. 产品默认工艺的新增、删除、大小写重复、空列表和排序。
4. 历史激光/折弯/焊接迁移幂等，创建跟进复制快照，完成/撤回顺序，已完成工艺不能删除。
5. 订单及组装模式的 0 数量、正数与 0 混合、全 0 拒绝、订单分配、补充发货、库存不足、重复提交和事务回滚。
6. 同客户产品搜索、重复产品合并、逐行备注长度与转义。
7. 新送货单快照稳定、历史送货单兼容、最后一列备注及 0 数量 PDF 输出。
8. 财务和对账排除 0 数量、纳入正数补充发货，并保持价格权限隔离。

专项测试通过后运行完整 Python/Node 回归。在隔离数据库中做启动迁移演练，并用本地浏览器检查产品列表批删弹窗、技术资料工艺编辑、生产工艺卡、两种发货模式、送货单页面和 PDF。完成后只提供本地验收，另获明确指令才部署。
