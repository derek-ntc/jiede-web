# 客户对账单、临时访问与在线签字设计

## 背景与目标

当前已发货清单可以查询普通订单发货和组装件发货，发货记录也已经保存含税单价与币种快照，但尚不能把选中的发货明细整理成客户对账单。业务需要参考现有《客户xxx公司对账单模版.xls》，生成可发给客户的 Excel，并允许客户通过临时链接核对、确认签字或提交异议。

本功能的目标是：

- 财务人员可在已发货清单中选择普通发货和组装件发货配件明细，生成一张独立对账单。
- 一张对账单只包含一个客户和一种货币，默认人民币 `CNY`。
- 发货价格按含税价格处理，并按 13% 增值税率反算不含税单价与金额。
- 对账单保存生成当时的客户、产品、发货与价格快照，后续基础资料变化不改写历史。
- 对账单可导出 `.xlsx`，版式参考用户提供的模板，并设置为 A4 横向打印。
- 系统生成高强度随机链接令牌和随机 6 位临时密码，访问有效期为 30 天。
- 客户验证密码后可确认并签字，或填写异议；确认签字后只允许查看，不能再次修改签名。
- 管理员可维护我方对账资料，自动填入对账单供应商信息区。

## 已确认决策

- 普通发货记录和组装件发货明细均可加入对账单。
- 发货价格为含税价，固定使用 13% 税率反算未税金额。
- 每张对账单只允许一种货币，默认人民币。
- 客户链接使用随机 6 位数字密码，有效期 30 天。
- 客户确认签字后，对账单仍可查看，但签名不可修改。
- 客户页面同时提供“确认并签字”和“提交异议”两条处理路径。
- 对账单采用独立业务记录，不与现有财务开票单状态自动联动。
- 增加“我方对账资料设置”，由管理员维护公司地址、联系人、电话和邮箱；公司名称默认“宁波市杰德机械科技有限公司”。

## 范围

### 包含

- 已发货清单中的普通发货与组装发货明细选择。
- 对账单创建、列表、详情、作废和重新生成访问密码。
- 对账单客户、供应商、发货与金额快照。
- 基于模板的 Excel 导出和 A4 横向打印设置。
- 客户公开访问、密码校验、访问期限、失败次数限制。
- 客户确认签字、提交异议以及后台状态展示。
- 我方对账资料设置。
- 权限检查、数据库迁移、审计字段和自动化测试。

### 不包含

- 自动通过短信、微信或邮件发送链接和密码；本期由工作人员复制后发给客户。
- 修改现有发票、开票和收款状态。
- 多税率、免税或逐行自定义税率；本期统一为 13%。
- 同一张对账单混用多种货币。
- 客户在线修改数量、价格或产品信息。
- 在已确认或已有异议的原对账单上直接改明细；需要纠错时作废并重新生成。
- 客户签字的数字证书、CA 认证或具有独立法律效力的电子签章服务。

## 方案选择

### 采用：独立对账单快照

对账单拥有独立主表、明细表、访问状态和客户操作记录。创建时复制所选发货的业务与金额数据，形成不可随基础资料变化的历史快照。

优点：可追溯、可安全分享、适合签字与异议流程，也不会误改开票状态。代价是需要新增表和管理页面，但边界最清楚。

### 不采用：每次临时拼接 Excel

仅从当前发货记录即时生成 Excel，开发量较小，但无法保证客户看到的内容与后来导出的内容一致，也无法可靠记录签字、异议和访问期限。

### 不采用：直接复用财务开票单

开票单与客户对账单的业务状态不同。把客户确认自动绑定到开票状态，会让“已确认、已开票、已收款”相互混淆，并增加误操作风险。

## 业务流程

### 后台生成

1. 财务人员进入“已发货清单”。
2. 勾选普通发货行或组装件发货中的具体配件行。
3. 点击“生成对账单”。
4. 服务端重新读取全部来源并验证：来源存在、客户一致、币种一致、价格完整、未被其他有效对账单占用。
5. 系统按发货价格快照计算含税与未税金额，保存对账单及明细快照。
6. 系统生成客户访问链接、6 位临时密码和 30 天到期时间。
7. 成功页仅在创建或重置密码后显示一次明文密码，并提供复制链接与密码的操作。

### 客户访问

1. 客户打开带随机令牌的公开链接。
2. 未过期且未作废时，页面要求输入 6 位临时密码。
3. 验证成功后，当前浏览器会话获得该对账单的临时访问权限，并显示对账明细与汇总。
4. 待客户处理状态下，客户可选择：
   - 确认无误，在签名板签字并提交；
   - 提交异议，填写必填的异议说明。
5. 确认后状态变为“已确认”，保存签名图片、签字人、确认时间、IP 与浏览器信息；页面只读。
6. 提交异议后状态变为“有异议”，保存异议内容、提交人、提交时间、IP 与浏览器信息；页面只读，工作人员审核后可作废并重新生成正确对账单。

客户完成签字后仍可在原 30 天有效期内重新打开并只读查看；到期后公开页面不再展示内容，但后台历史记录和导出不受影响。

### 后台处理

- 对账单状态为：`pending`（待客户处理）、`confirmed`（已确认）、`disputed`（有异议）、`void`（已作废）。
- 已确认和有异议的记录均保留快照与客户操作痕迹，不允许直接修改。
- 作废只改变状态并立即失效公开访问，不物理删除记录。
- 待处理对账单可重置访问凭证；系统同时生成新链接令牌和新临时密码，旧链接、旧密码和已有公开会话立即失效，到期时间重新从重置时计算 30 天。
- 已确认或有异议的对账单不允许重置为可操作状态；需要更正时作废并新建。

## 发货来源与去重

### 普通发货

普通发货以 `product_order_shipments.id` 为来源，快照包含：

- 发货日期、送货单号或系统发货编号、采购订单号。
- 产品 ID、物料编码/SKU、产品图号、产品名称、单位。
- 发货数量、含税单价、币种、含税行金额。

### 组装件发货

组装件本身不是产品，对账时按 `assembly_shipment_items.id` 的实际配件明细计价。快照额外包含组装发货批次 ID、组装件图号和对应订单分配信息。采购订单号按该配件的订单分配汇总展示；无订单部分明确显示“无订单”。

### 有效占用

同一普通发货记录或组装发货配件明细，同一时间只能出现在一张非作废对账单中，避免重复对账。作废后来源可重新加入新对账单。约束由事务内复查和数据库唯一有效占用共同保证，不能只依赖页面禁用。

## 金额与税额规则

所有计算使用十进制或整数最小货币单位，不使用二进制浮点数。

- 税率固定为 `13%`，并在对账单主表保存税率快照 `130000`（百万分比表示）或等价精确值。
- 含税单价取发货时保存的价格快照；没有价格的来源不能生成对账单。
- 含税行金额 = 含税单价 × 发货数量。
- 不含税单价 = 含税单价 ÷ 1.13，展示到 6 位小数。
- 不含税行金额 = 含税行金额 ÷ 1.13，按币种最小单位四舍五入。
- 税额 = 含税行金额 − 不含税行金额。
- 汇总金额由已经舍入的各行金额求和，避免页面、Excel 与数据库出现分币差异。
- 金额、税率、数量和总计均由服务端计算，浏览器提交值不作为可信数据。

人民币默认显示 `RMB/CNY`。数据库统一保存标准代码 `CNY`；Excel 货币标识可显示为“RMB”。

## 客户与供应商资料

### 客户快照

生成对账单时从客户资料复制：

- 客户公司名称。
- 地址、电话、邮箱。
- 普通联系人作为采购联系人。
- 对账联系人未单独配置时沿用普通联系人。
- 开票抬头、税号、注册地址、注册电话、开户银行、银行账号与收票邮箱，供后续后台核对使用；模板未展示的字段不强行放入首版表格。

客户资料后续修改不影响历史对账单。首版不增加重复的客户对账联系人字段；若以后业务需要不同联系人，可在客户资料中扩展，对历史快照保持兼容。

### 我方对账资料设置

增加单例配置，包含：

- 公司名称，默认“宁波市杰德机械科技有限公司”。
- 地址。
- 联系人。
- 电话。
- 邮箱。

仅管理员可修改。生成对账单时把当前配置复制到对账单快照，因此之后修改设置不会改变既有对账单。

## 数据模型

### `reconciliation_company_profile`

单例我方资料表：

| 字段 | 说明 |
| --- | --- |
| `id` | 固定单例主键 |
| `company_name` | 公司名称 |
| `address` | 地址 |
| `contact` | 联系人 |
| `phone` | 电话 |
| `email` | 邮箱 |
| `updated_by` / `updated_at` | 修改审计 |

### `reconciliation_statements`

对账单主表保存：

- 对账单号、所属月份或账期起止日期、创建时间和创建人。
- 客户 ID，以及客户名称、地址、电话、邮箱、采购联系人、对账联系人和开票资料快照。
- 我方公司名称、地址、电话、邮箱和联系人快照。
- 币种、税率、含税总额、不含税总额和税额。
- 状态、备注、作废原因、作废人和作废时间。
- 公开令牌摘要、密码哈希、访问到期时间、密码版本、失败次数和临时锁定时间。
- 客户确认人、确认时间、签名图片文件名、确认 IP 和 User-Agent。
- 异议提交人、异议内容、提交时间、IP 和 User-Agent。

对账单号由服务器生成并保证唯一，例如 `DZ-202609-0001`。令牌只以 SHA-256 摘要入库；6 位密码仅保存强密码哈希，明文只在生成或重置时返回一次。

### `reconciliation_statement_items`

对账明细保存：

- 对账单 ID、排序号。
- 来源类型 `ordinary` 或 `assembly_item`，以及来源 ID。
- 发货日期、送货单号、采购订单号、组装批次和组装件图号快照。
- 产品 ID、物料编码、产品图号、名称、规格型号和单位快照。
- 数量、币种、含税单价、不含税单价、含税金额、不含税金额、税额。
- 备注及创建时间。
- 有效占用标记，用于限制来源不能进入两张非作废对账单。

数据库迁移沿用项目现有的幂等 `ensure_*` 方式，只新增表、索引和必要字段，不覆盖已有数据。

## 公开访问安全

- 链接令牌使用密码学安全随机数，至少 32 字节，不使用可猜测的自增 ID。
- 令牌摘要和密码哈希分别保存；数据库泄露时不直接暴露可用链接或明文密码。
- 密码固定为 6 位数字，允许保留前导零。
- 同一令牌连续输错 5 次后锁定 15 分钟；成功验证后清零失败计数。
- 公开验证成功状态写入服务器签名会话，并绑定对账单 ID 与密码版本；重置密码、作废或过期会使已有会话失效。
- 公开页面和接口不泄露其他对账单是否存在，也不返回后台内部 ID、价格权限或客户管理数据。
- 客户确认与异议提交均采用 CSRF 防护、一次性状态校验和数据库条件更新，防止重复提交覆盖结果。
- 签名沿用现有 PNG 签字图校验能力，限制尺寸、像素、文件大小和解码格式；文件名由服务器生成，不能使用用户路径。
- 签名文件通过受控路由读取，不暴露上传目录，也不允许目录遍历。

## 权限模型

后台对账单涉及价格和客户财务信息，首版仅允许管理员或拥有 `finance_manage` 权限的用户访问和操作。

| 操作 | 权限 |
| --- | --- |
| 勾选发货并生成对账单 | `finance_manage` |
| 查看、搜索、导出对账单 | `finance_manage` |
| 重置访问凭证、作废待处理/异常对账单 | `finance_manage` |
| 修改我方对账资料 | 管理员 |
| 客户查看与提交 | 有效公开令牌 + 临时密码会话 |

后台查询、详情、导出和接口均在服务端检查权限。没有财务权限的用户不查询、不序列化且不渲染价格或对账入口。

## 页面设计

### 已发货清单

- 普通发货行保留现有勾选框。
- 组装发货卡片的每条配件明细增加勾选框，值由来源类型和 ID 组成，服务端不信任隐藏字段中的客户或金额。
- 增加“生成对账单”按钮，仅对有财务权限的用户显示。
- 勾选跨客户、跨币种、价格缺失或已经对账的来源时，在服务端返回明确提示，并且不创建任何记录。

### 对账单后台

新增“对账单”子页面，包括：

- 按对账单号、客户、日期和状态筛选的列表。
- 详情页展示客户/我方资料、明细、含税/未税汇总、访问状态、签名或异议。
- “下载 Excel”“重置访问凭证”“作废”操作。
- 创建或重置后显示一次“客户链接 + 临时密码”，提供复制按钮并明确到期日期；之后不保存或重新显示明文凭证。

### 客户页面

- 登录页只显示公司名称、对账单号后部掩码、密码框与到期提示。
- 验证后详情页显示完整对账表、金额汇总和当前状态。
- 待处理时显示签字板、签字人姓名和确认按钮，以及独立的异议说明输入区。
- 已确认时显示签名、签字人和确认时间；有异议时显示已提交提示；两者均不再显示可提交控件。
- 手机端允许横向滚动查看明细，桌面端保持紧凑的 SAP 风格表格。

## Excel 版式

Excel 输出参考用户提供模板的业务结构，不直接依赖原 `.xls` 文件运行时读取：

- 顶部居中标题：“YYYY年M月对账单”；跨月时显示账期起止日期。
- 左侧客户信息，右侧供应商信息。
- 明细列依次为：序号、送货日期、送货单号、采购订单号、物料编码、物料名称、规格型号、单位、送货数量、不含税单价、含税单价、不含税金额、含税金额、备注。
- 明细行数量动态扩展，汇总区自动下移。
- 汇总区保留本期销售合计、不含税金额、含税金额和税额；开票金额、结算金额等没有可靠系统事实的字段不伪造，可保留空白供财务填写或明确标注“未登记”。
- 底部保留制单人、复核人、日期、备注以及双方采购/财务签字区域。
- 客户尚未确认时，客户签字区留空；确认后再次导出时嵌入已保存的客户签名，并填写签字人和确认日期。
- 使用清晰黑色字体、加深边框和紧凑表格，保持与现有系统列表风格一致。
- 页面设置固定为 A4 横向、水平 1 页宽、纵向自动分页、重复打印明细表头，并设置合理页边距与打印区域。
- 数字单元格写入真正的数值类型并使用货币格式，不把金额写成文本。
- 总计使用 Excel 公式，同时由服务端保存对应总额；导出前测试两者一致。
- 首版输出 `.xlsx`，不输出旧 `.xls`，以保证公式、打印设置和兼容性。

## 路由与服务边界

建议新增独立帮助函数或服务层职责：

- 规范化普通与组装发货来源。
- 校验客户、币种、价格和有效占用。
- 精确计算税前/税后金额与汇总。
- 在单一事务中创建对账单和明细快照。
- 生成并验证公开令牌、密码与临时会话。
- 保存不可变客户确认或异议结果。
- 生成动态行数的对账单 Excel。

路由分为：

- 后台对账单列表、创建、详情、导出、重置密码、作废和我方资料设置。
- 公开对账单密码验证、查看、确认签字和提交异议。

所有状态变更均采用 POST；下载和只读详情使用 GET。创建、客户提交、重置和作废在数据库事务中完成。

## 错误处理

主要提示包括：

- “请选择至少一条发货明细”。
- “一张对账单只能包含同一客户的发货记录”。
- “一张对账单只能使用一种货币”。
- “部分发货记录没有价格，不能生成对账单”。
- “部分发货记录已加入其他有效对账单”。
- “对账单已过期或已作废”。
- “临时密码不正确，请重试”。
- “尝试次数过多，请 15 分钟后重试”。
- “该对账单已经确认，签名不能修改”。
- “请填写异议说明”。

任何一条来源校验失败，整张对账单均不创建；不能部分成功。
