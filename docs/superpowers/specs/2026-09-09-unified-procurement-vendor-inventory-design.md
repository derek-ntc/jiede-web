# 统一采购、客商管理、采购库存与财务联动设计

## 目标

本次升级把当前分散的“其他采购”“纸箱采购”“到货记录”和外协采购整合为一套可追溯的采购系统，并与供应商、独立采购库存、采购领用出库及财务开票形成闭环。

升级后应实现：

1. 顶部仅保留一个“采购”入口，内部按原材料、纸箱、外协加工、其他采购和到货记录分类。
2. 四类采购共用统一的采购订单、状态、供应商和到货流程，同时按类别显示不同明细字段。
3. 采购订单可导出横向 A4 的 Excel 和 PDF，版式参考用户提供的采购订单截图。
4. 到货时按采购订单复核实际数量、合格数量和库位，支持分批到货及批量入库。
5. 采购货物进入独立的采购库存，不增加或减少现有产品、配件和成品库存。
6. 采购库存可按类别、供应商、名称、库位和开票状态查询，并可生成入库清单。
7. 发货模块增加采购货物出库，支持多选、领用人、数量、日期、备注和出库清单。
8. 客户、供应商及常用资料统一归入“客商管理”。
9. 财务可按客户查询已发货明细，勾选后生成开票清单，并避免重复开票。
10. 现有其他采购、纸箱采购和到货记录全部迁移保留，并记录原始来源。

## 非目标

- 外协加工件不匹配产品列表，也不进入现有产品库存。
- 不把采购订单直接转换为生产订单。
- 本阶段不实现供应商在线确认、电子签章或外部访问链接。
- 本阶段不实现采购审批流、付款计划、应付账款或复杂税率核算。
- 不自动覆盖同名但资料冲突的历史供应商。
- 设计确认和实施计划阶段不修改正式 VPS 数据；部署必须另获明确指令。

## 现状

当前系统存在四组彼此割裂的数据：

- `purchase_followups` 只保存物品、数量、采购日期、备注和图片，没有正式采购订单、供应商、到货或库存关系。
- `carton_purchases`、`carton_products` 和 `carton_suppliers` 独立维护纸箱采购、产品模板及供应商，并能生成纸箱采购单 PDF。
- `arrival_records` 和 `arrival_suppliers` 是手工到货台账，不能关联采购订单，也不会形成库位库存。
- 喷塑模块另有 `powder_coating_*` 供应商和加工记录，但它的业务语义与本次通用外协采购不完全相同。

现有产品库存以 `manuals` 为核心，`inventory_balances` 和 `inventory_transactions` 都要求关联产品。直接复用会把原材料、纸箱和消耗品混入产品库存，因此本设计建立独立采购库存账。

财务模块已经能够从普通发货、组装发货和补充发货中形成开票来源。本次保留现有财务状态机，在界面上补齐按客户检索和勾选清单的入口及验收覆盖。

## 信息架构与导航

### 采购

顶部原有“其他采购”“纸箱采购”“到货记录”入口合并为一个“采购”。采购页面使用子页面切换：

- 原材料采购
- 纸箱采购
- 外协加工
- 其他采购
- 到货记录

四个采购分类共享订单列表和新建入口，分类决定默认字段、筛选条件和文档列。到货记录是统一采购订单的下游操作，不再作为孤立手工台账。

### 客商管理

顶部“客户信息”和“常用信息”归并为“客商管理”，包含：

- 客户信息：保留现有页面、字段、开票资料和业务行为。
- 供应商信息：新增统一供应商档案管理。
- 常用信息：保留现有通用资料，并增加公司收货地址模板。

### 库存、发货和财务

- 库存增加“采购库存”子页面，现有产品库存保持不变。
- 发货增加“采购货物出库”子页面，现有产品发货保持不变。
- 财务保留现有开票单状态与详情页，并明确提供按客户筛选已发货明细后生成开票清单的入口。

## 数据模型

### 统一供应商

新增 `suppliers`：

- `id`
- `code`：唯一供应商代码，可自动生成后人工修改
- `name`：唯一供应商名称
- `contact`
- `phone`
- `email`
- `address`
- `remark`
- `active`
- `legacy_source`、`legacy_id`
- `created_at`、`updated_at`

已经被采购订单引用的供应商不能物理删除，只能停用。采购订单同时保存供应商快照，后续修改供应商档案不改变历史采购订单。

### 公司收货模板

新增 `purchase_delivery_profiles`：

- `id`
- `name`
- `delivery_address`
- `recipient`
- `phone`
- `default_remark`
- `is_default`
- `active`
- `created_at`、`updated_at`

同一时间只允许一条启用的默认模板。新建采购订单时自动带出默认模板，订单内可以修改；保存后的订单使用快照，不再随模板变化。

### 采购订单

新增 `purchase_orders`：

- `id`、唯一 `order_no`
- `category`：`raw_material`、`carton`、`outsourcing`、`other`
- `supplier_id`
- 供应商代码、名称、联系人、电话、邮箱、地址快照
- `purchased_at`
- 收货地址、收件人、联系电话、订单备注快照
- `currency`，默认 `RMB`
- `status`：`draft`、`ordered`、`partially_received`、`received`、`cancelled`
- `legacy_source`、`legacy_id`
- 创建人、更新人和时间

订单号由服务端生成且唯一。草稿可以编辑；已下单订单允许在没有到货的范围内修改，修改数量不得低于累计到货数量。取消订单不会删除历史记录。

新增 `purchase_order_items`：

- `id`、`purchase_order_id`、`sort_order`
- `item_name`、`drawing_no`
- `material`
- `length`、`width`、`height`、`thickness`
- `dimension_text`：无法拆分成长宽高时保存自由文本尺寸
- `surface`
- `spec`
- `unit`
- `ordered_quantity`
- `unit_price_minor`、`line_total_minor`
- `expected_at`
- `remark`
- `legacy_source`、`legacy_id`
- 创建及更新时间

金额使用人民币分整数保存。页面和文档按类别隐藏无关字段，但数据库采用统一字段集，以便跨类别查询和迁移。

### 到货与检验

新增 `purchase_receipts`：

- `id`、唯一 `receipt_no`
- `purchase_order_id`
- `received_at`
- `status`：`draft`、`posted`、`voided`
- `remark`
- 创建人、过账人和时间

新增 `purchase_receipt_items`：

- `id`、`receipt_id`、`purchase_order_item_id`
- `actual_quantity`
- `qualified_quantity`
- `location_id`
- `invoice_status`：`not_required`、`pending`、`invoiced`
- `remark`
- `inventory_lot_id`

`actual_quantity` 是本批实际收到数量，`qualified_quantity` 是其中本次入库数量，必须满足 `0 <= qualified_quantity <= actual_quantity`。允许同一订单分批到货。累计实际到货超过订购数量时需要二次确认，并在订单和入库清单中标识超收。

只有已过账且合格数量大于零的明细进入采购库存。草稿可以修改；过账后以冲销记录纠错，不直接改写已经产生的库存流水。

### 采购库存

采购库存使用独立表，不关联 `manuals`：

采购库存复用现有 `warehouse_locations` 库位主数据，因此产品库存和采购库存看到的是同一套真实库位编号、名称和启用状态；两类库存仍分别使用独立的余额表、批次和流水，不会互相增减。

新增 `purchase_inventory_lots`：

- `id`
- `category`
- `item_name`、`drawing_no`、`material`、`spec`、尺寸、厚度、表面、单位快照
- `supplier_id` 及供应商名称快照
- `purchase_order_id`、`purchase_order_item_id`、`receipt_item_id`
- `location_id`
- `received_quantity`
- `available_quantity`
- `unit_price_minor`、`currency`
- `invoice_status`
- `received_at`
- 创建及更新时间

新增 `purchase_inventory_transactions`：

- `id`、唯一 `transaction_no`
- `lot_id`、`location_id`
- `type`：`receipt`、`outbound`、`adjustment`、`reversal`
- `quantity_delta`
- `related_type`、`related_id`
- 操作人、备注和时间

每次余额变化都写流水。库存调整要求专门权限、原因和审计信息，不允许直接编辑余额字段。

### 采购货物出库

新增 `purchase_inventory_outbounds`：

- `id`、唯一 `outbound_no`
- `used_by`：领用人
- `outbound_at`
- `remark`
- `status`：`posted`、`voided`
- 创建人及时间

新增 `purchase_inventory_outbound_items`：

- `id`、`outbound_id`、`lot_id`
- 物品、供应商、规格、单位和库位快照
- `quantity`
- `remark`

出库在同一事务中校验并扣减采购库存，不允许负库存。作废通过反向流水恢复原批次库存。

## 分类字段与页面行为

### 原材料采购

明细默认显示：材质、长、宽、厚度、表面、数量、单位、预计到货时间和其他要求。物品名称可选填；为空时文档以“材质 + 尺寸”作为显示名称。

### 纸箱采购

明细默认显示：材质、长、宽、高、数量、单位、单价、合计、预计到货时间和其他要求。可从迁移后的纸箱模板带出尺寸和价格，但保存前允许修改。

### 外协加工

明细默认显示：物品名称或图号、材质、尺寸、厚度、表面、数量、单位、可选单价、预计到货时间和其他要求。到货后只进入“外协加工件库存”，不尝试匹配产品列表。

### 其他采购

明细默认显示：物品名称、规格、材质、尺寸、厚度、表面、数量、单位、可选单价、预计到货时间和其他要求。丝攻、螺栓等物品可以仅填名称、规格和数量，其余字段留空。

### 通用交互

- 一个采购订单可以连续新增、删除和排序多行。
- 供应商、采购日期和至少一条有效明细为必填。
- 数量必须大于零；单价为空按“未录入价格”处理，不等同于免费。
- 合计由服务端使用单价和数量重新计算，不能只信任浏览器提交值。
- 订单列表可按类别、供应商、订单号、物品关键词、采购日期、预计到货日期和状态筛选。

## 采购订单 Excel 与 PDF

Excel 和 PDF 都采用横向 A4，整体布局参考用户提供的截图：

1. 顶部居中“采购订单”，右侧显示订单号。
2. 供应商区显示名称、代码、联系人、电话、邮箱和地址。
3. 明细区按采购类别生成列；原材料优先呈现材质、长、宽、厚度、数量、备注和到货时间。
4. 底部显示公司常用送货地址、收件人、联系电话、订单备注和公司联系资料。
5. Excel 设置打印区域、横向纸张、适合一页宽、重复表头和页边距；可以继续修改后打印。
6. PDF 固定版式，适合直接发送供应商。

导出使用订单保存时的供应商和收货快照，确保历史文件可复现。文件名包含采购订单号，不使用当前时间替代业务编号。

## 到货、批量入库与采购库存查询

到货页首先按订单号、供应商、类别、物品和未完成状态查找采购订单。进入订单后展示订购数量、历史累计实际到货、历史累计合格入库及本次可录数量。

用户可以：

- 逐行填写本批实际数量和合格数量；
- 为每行选择采购库位；
- 设置“不需要开票”“需要开票/未开票”或“已开票”；
- 勾选多行一次过账；
- 生成本次入库清单。

订单根据累计到货自动更新为未到货、部分到货或全部到货。某一行未到齐不阻止其他行入库。重复提交使用幂等标识避免产生两次库存。

采购库存页面按原材料、纸箱、外协加工件和其他物品分类，支持供应商、名称/图号、规格、库位、入库日期及开票状态筛选。列表显示入库数量、当前可用数量、单价、订单号、到货单号和所在库位。没有价格权限时隐藏单价和金额。

开票状态保存在到货批次/库存批次级别，允许同一采购订单的不同到货批次处于不同状态。已全部出库的批次仍保留在历史查询中。

## 采购货物出库

“发货”下新增“采购货物出库”，名称沿用用户业务用语，但它是内部领用出库，不进入客户送货单或销售财务来源。

操作流程：

1. 按类别、供应商、物品名称、规格和库位查找有库存批次。
2. 勾选一个或多个批次。
3. 填写领用人、日期、逐行数量及整单/逐行备注。
4. 服务端重新读取可用数量并在事务中校验。
5. 保存出库单、明细和负向库存流水。
6. 生成横向 A4 的出库清单；支持页面打印、Excel 和 PDF。

同一物品存在多个到货批次时，默认展示批次、供应商和库位，由用户明确选择，不自动跨批次扣减。后续如需要先进先出，可以另行设计。

## 客商管理

客户页面、客户开票资料和现有权限保持不变。统一供应商页面提供新增、编辑、停用、恢复和搜索。

历史供应商迁移来源包括 `carton_suppliers`、`arrival_suppliers`、`powder_coating_suppliers` 以及记录表中的自由文本供应商名称。迁移规则：

- 名称规范化仅去除首尾空格，不擅自合并名称相似但不相同的公司。
- 同名且非空字段不冲突时合并补齐。
- 同名但联系人、电话或地址冲突时建立一条供应商并生成迁移冲突报告，由管理员后续选择正确资料；不静默覆盖。
- 原采购及到货记录保存 `legacy_source`、`legacy_id`，支持追溯。

常用信息增加公司收货模板维护。原有常用信息数据原样保留，不强制转换为结构化地址。

## 财务开票联动

财务“新建开票清单”页面按客户加载尚未被有效开票单占用的已发货明细，并支持发货日期、订单号和送货单号筛选。

用户勾选明细后：

- 生成客户开票资料快照；
- 汇总数量、含税单价和含税金额；
- 默认货币为 RMB；
- 保存来源类型和来源 ID，使用唯一有效占用键防止重复开票；
- 沿用待开票、已开票、已收款、作废状态和现有导出功能。

数量为零的送货单展示行不成为财务来源。缺少价格的正数发货行在选择时明确提示，未补齐价格前不能生成金额不完整的开票清单。

## 权限

账号管理增加以下独立权限：

- 查看采购
- 新建及编辑采购订单
- 到货和采购入库
- 查看采购库存
- 调整采购库存
- 采购货物出库
- 查看采购价格及金额
- 管理供应商和采购常用资料

管理员默认拥有全部权限。旧账号迁移时根据现有采购、纸箱采购、库存、财务和价格权限映射初始值，避免升级后意外扩大普通账号权限。

服务端必须独立执行权限校验；只隐藏页面按钮不算权限控制。Excel/PDF 导出也遵循价格权限，无价格权限的采购订单和库存清单不输出单价与金额。

## 一致性、错误与审计

- 新建/编辑订单、到货过账、库存调整、出库及作废都使用数据库事务和现有应用写锁。
- 到货过账和出库提交前重新校验订单余额、库位状态和库存余额。
- 所有形成库存变化的操作都使用唯一幂等键；重复提交返回原结果，不重复记账。
- 已过账到货和出库不直接删除，采用作废及反向流水。
- 供应商、采购订单和库存批次保存必要快照，主数据修改不影响历史文档。
- 用户输入在 HTML、Excel 和 PDF 中转义或按纯文本处理；对超长备注、非法日期、负数和超限金额进行服务端校验。
- 采购金额和销售财务金额分属不同业务域；本次采购开票状态仅作为进项票跟踪，不写入销售开票单。

## 历史数据迁移

迁移以新增表和幂等回填为主，不删除旧表。步骤如下：

1. 建立统一供应商并生成冲突清单。
2. 将纸箱采购转为 `carton` 采购订单及明细，保留下单、到货、完成、价格和原始 ID。只有原记录明确填写到货日期时才生成历史到货批次；仅勾选“完成”但没有到货日期时保留完成来源标记，不推定已经入库。
3. 将其他采购跟进转为 `other` 订单或草稿：有采购日期的记录标记为已下单，没有采购日期的记录保留为草稿；图片引用继续保留。
4. 将孤立到货记录转为带“历史到货导入”来源的采购订单、到货单和采购库存批次，避免伪造与不存在的新订单关联。
5. 旧表暂时只读保留一个发布周期；新页面全部读取统一表。
6. 对迁移前后记录数、数量合计、金额合计、供应商覆盖率和原始 ID 唯一性生成报告。

历史到货没有库位时进入显式的“待分配库位”状态，不虚构实际库位；分配库位后才可参与正常出库。历史记录没有开票信息时默认“需要开票/未开票”，但迁移报告中单独统计，便于人工复核。

## 分阶段实施与验收边界

### 阶段一：客商管理与采购订单

- 统一供应商、收货模板和导航。
- 四类采购订单及列表。
- Excel/PDF 横向 A4 导出。
- 旧采购及供应商迁移预演和报告。

阶段一不产生采购库存。

### 阶段二：到货与采购库存

- 采购订单选择、分批到货、复核和批量入库。
- 采购库位、批次余额、库存流水、开票三态和入库清单。
- 历史到货迁移。

### 阶段三：采购货物出库

- 发货页子页面、多选领用出库、库存校验、作废恢复。
- 页面打印、Excel 和 PDF 出库清单。

### 阶段四：财务开票入口

- 按客户、日期、订单号和送货单号查询发货来源。
- 勾选生成开票清单、缺价提示和防重复占用。
- 验证现有开票、收款、作废及导出行为不回归。

每阶段完成后单独验收，再进入下一阶段。部署时一次只部署已经通过完整回归和迁移演练的阶段。

## 测试与验收

按测试驱动方式实施，至少覆盖：

1. 四类采购订单字段、校验、多行增删、状态转换、供应商/收货资料快照。
2. 订单号唯一性、并发提交、金额分计算和无价格权限隔离。
3. Excel/PDF 横向 A4 的表头、分类列、分页、合计、公司收货信息和中文字体。
4. 分批到货、部分/全部状态、超收二次确认、合格数量边界和批量过账原子性。
5. 采购库存按类别、供应商、名称、库位和开票三态筛选；产品库存完全不受影响。
6. 多批次同物品、库位禁用、余额不足、并发出库、作废反向流水和出库清单。
7. 供应商合并、冲突报告、停用、引用保护和历史快照稳定。
8. 三套旧数据的幂等迁移、数量/金额对账、原始来源追溯和待分配库位处理。
9. 财务按客户选择发货明细、防重复开票、缺价阻止、零数量排除及现有状态机回归。
10. 新权限的页面、接口、Excel 和 PDF 访问控制。

专项测试通过后运行完整 Python、Node 和真实浏览器回归。在正式部署前复制正式数据库和附件做隔离迁移演练，输出迁移统计及差异；部署前创建可恢复备份，部署后核对服务状态、页面、关键表数量、库存余额和数据库完整性。
