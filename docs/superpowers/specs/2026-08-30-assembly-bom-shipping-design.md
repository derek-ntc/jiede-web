# 组装件配件配置与组装发货设计

## 背景与目标

当前产品列表中的每一条记录代表一个实际配件产品，发货操作只能从未发完订单中逐项选择产品并填写数量。业务需要在不把“组装件”创建为产品的前提下，为配件维护一个或多个组装件归属及单套用量，并在发货时按客户、组装件图号和套数自动展开配件数量。

本功能的目标是：

- 一个配件可以属于多个组装件，每个关系具有独立的单套用量。
- 组装件图号只是配件属性，不是产品列表中的产品记录。
- 组装配置按客户隔离；发货时先选客户，再选择该客户配置过的组装件图号。
- 输入组装件套数后，自动计算全部配件的默认发货数量，并允许人工逐项修改。
- 优先匹配该客户现有的未发订单；没有订单或订单数量不足时仍允许发货，但必须明确警告。
- 库存不足时仍允许用户确认发货，库存最低扣到零，不产生负库存，并记录缺口。
- 所有组装发货保留可审计的历史快照，后续修改组装配置不改变历史记录。

## 范围

### 包含

- 产品编辑页中的组装关系增删和校验。
- 现有已发货页面中的“按组装件发货”模式。
- 客户和组装件联动选择、数量自动计算、订单自动分配、库存预检查与警告确认。
- 有订单发货和无订单直接发货的统一批次记录。
- 组装发货记录在现有已发货页面中的展示。
- 组装发货的修改、删除、订单汇总同步与库存同步。
- 发货图片、发货日期和备注在组装发货批次上的保存。
- 数据库迁移及自动化回归测试。

### 不包含

- 将组装件创建为产品、库存物料或订单产品。
- 组装件自身的库存管理。
- 多级 BOM 或组装件嵌套。
- 小数用量；本期所有数量均为正整数。
- 负库存；库存不足时只扣减实际可用库存。
- 改变现有普通订单发货入口和行为。

## 领域规则

### 组装配置

每个组装关系包含：

- `manual_id`：配件产品 ID。
- `assembly_drawing_no`：组装件图号，去除首尾空格后不能为空。
- `quantity_per_set`：每套所需配件数量，必须是正整数。
- `sort_order`：在编辑页和发货明细中的稳定显示顺序。
- 创建时间和更新时间。

同一产品不能重复配置相同的组装件图号。组装配置不单独存储客户，而是通过产品当前的 `manuals.customer` 归属客户。因此修改产品客户后，该产品的全部组装关系自动归到新客户下。

产品只要配置至少一条组装关系，就必须选择非空客户；否则保存产品时提示“请先选择客户，再配置所属组装件”并拒绝保存。未配置组装关系的产品仍允许客户为空。

发货时可选组装件的集合为：所选客户的产品记录所关联的去重组装件图号。相同文本的组装件图号在不同客户下是彼此独立的配置。

### 数量计算

用户输入正整数套数后，每个配件的默认数量为：

```text
默认数量 = 组装件套数 × 单套用量
```

用户可把每个配件的“实际发货数量”修改为任意正整数。保存时服务器以用户最终数量为准，但仍保留套数、单套用量和原始计算数量作为历史快照。

### 订单匹配

服务器按以下规则为每个配件的最终发货数量分配订单：

1. 只匹配产品 ID 和客户均一致、且仍有未发数量的订单。
2. 按 `planned_ship_at` 升序排列；空日期排在有日期之后。
3. 计划日期相同时，按 `ordered_at`、`created_at`、订单 ID 升序排列。
4. 依次占用各订单的未发数量，直到配件发货数量全部分配或无更多订单。
5. 未能分配的剩余数量记录为无订单直接发货，不创建虚假订单。

订单分配必须在最终保存事务中重新计算。预览后如果订单状态变化，服务器返回最新分配和警告，要求用户基于新状态再次确认。

### 库存处理

服务器使用现有产品库存余额检查每个配件：

- 库存足够：扣减完整的实际发货数量。
- 库存不足：显示缺口；用户确认后，库存只扣减到零。
- 实际库存扣减数量为 `min(当前可用库存, 实际发货数量)`。
- 缺口数量为 `实际发货数量 - 实际库存扣减数量`。
- 发货历史同时保存请求发货数量、实际库存扣减数量和库存缺口，避免把“发货数量”与“库存账面扣减数量”混为一谈。

库存检查和扣减在同一保存事务中完成。如果预览后库存变化，服务器返回新的警告并要求再次确认。

## 数据模型

### `product_assembly_components`

保存当前有效的产品组装关系：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | INTEGER PK | 主键 |
| `manual_id` | INTEGER NOT NULL FK | 配件产品；删除产品时级联删除 |
| `assembly_drawing_no` | TEXT NOT NULL | 组装件图号 |
| `quantity_per_set` | INTEGER NOT NULL | 单套用量，正整数 |
| `sort_order` | INTEGER NOT NULL | 显示顺序 |
| `created_at` | TEXT NOT NULL | 创建时间 |
| `updated_at` | TEXT NOT NULL | 更新时间 |

唯一约束：`(manual_id, assembly_drawing_no)`。

### `assembly_shipment_batches`

保存一次完整的组装发货操作：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | INTEGER PK | 批次主键 |
| `customer` | TEXT NOT NULL | 发货时客户快照 |
| `assembly_drawing_no` | TEXT NOT NULL | 发货时组装图号快照 |
| `set_quantity` | INTEGER NOT NULL | 输入套数 |
| `shipped_at` | TEXT NOT NULL | 发货日期 |
| `logistics_no` | TEXT NOT NULL | 发货备注/物流信息 |
| `created_by` | TEXT NOT NULL | 操作人 |
| `created_at` | TEXT NOT NULL | 创建时间 |
| `updated_at` | TEXT NOT NULL | 更新时间 |

发货图片与批次关联，避免同一张图片被复制到每个配件明细。

### `assembly_shipment_items`

保存每个配件的历史快照和库存结果：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | INTEGER PK | 明细主键 |
| `batch_id` | INTEGER NOT NULL FK | 所属组装发货批次；删除批次时级联删除 |
| `manual_id` | INTEGER NOT NULL FK | 配件产品 |
| `drawing_no` | TEXT NOT NULL | 发货时配件图号快照 |
| `product_name` | TEXT NOT NULL | 发货时产品名称快照 |
| `quantity_per_set` | INTEGER NOT NULL | 发货时单套用量快照 |
| `calculated_quantity` | INTEGER NOT NULL | 套数乘单套用量 |
| `shipped_quantity` | INTEGER NOT NULL | 用户最终确认数量 |
| `inventory_deducted_quantity` | INTEGER NOT NULL | 实际库存扣减量 |
| `inventory_shortage_quantity` | INTEGER NOT NULL | 库存缺口 |
| `created_at` | TEXT NOT NULL | 创建时间 |
| `updated_at` | TEXT NOT NULL | 更新时间 |

### `assembly_shipment_allocations`

保存配件数量向订单的分配结果：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `id` | INTEGER PK | 主键 |
| `item_id` | INTEGER NOT NULL FK | 组装发货配件明细 |
| `order_id` | INTEGER FK NULL | 匹配的订单；为空代表无订单直接发货 |
| `quantity` | INTEGER NOT NULL | 分配数量，正整数 |
| `created_at` | TEXT NOT NULL | 创建时间 |

每个明细的 allocation 数量合计必须等于该明细的 `shipped_quantity`。有订单 allocation 同步进入现有订单已发数量汇总；空订单 allocation 明确显示为“无订单直接发货”。

### `assembly_shipment_images`

字段沿用现有发货图片元数据，包括文件名、原文件名、内容类型、大小、上传时间、IP 和 User-Agent，并通过 `batch_id` 关联组装发货批次。

## 服务边界

为避免继续扩大单体路由中的重复业务逻辑，组装功能拆为可独立测试的帮助函数：

- 解析并校验产品编辑页提交的组装关系。
- 保存和读取产品组装关系。
- 查询客户可用组装图号及其配件定义。
- 根据套数展开配件默认数量。
- 按既定顺序分配未发订单。
- 计算库存扣减和缺口。
- 生成发货预览响应。
- 在单一事务中保存批次、明细、订单分配、库存流水和图片。
- 修改或删除批次时反向同步订单汇总及库存。

普通订单发货继续使用现有代码路径。组装发货复用现有订单汇总、库存流水、文件校验和权限检查规则，但不通过伪造订单复用现有入口。

## 产品编辑界面

“编辑产品资料”页面增加“所属组装件”编辑表格。每行包含组装件图号、每套用量和删除按钮，并可动态增加行。

提交行为：

- 空白行忽略。
- 只填写一个字段的半空行报错。
- 单套用量必须为正整数。
- 同一产品内重复图号报错。
- 校验失败时返回编辑页并显示明确错误，不保存任何组装关系。
- 保存时以当前提交集合替换该产品原有组装关系。

本期不在新增产品表单中配置组装关系；先创建产品，再从产品列表进入编辑页维护，符合用户指定的操作入口。

## 组装发货界面

现有“已发货订单 → 发货操作”区域增加模式选择：

- 按订单发货：保持当前界面和行为。
- 按组装件发货：显示新的组装发货表单。

组装发货表单流程：

1. 选择客户。
2. 加载并选择该客户可用的组装件图号。
3. 输入正整数套数。
4. 页面自动显示全部配件明细：配件图号、名称、单套用量、计算数量、可编辑实际数量、订单状态和库存状态。
5. 点击保存时先向服务器提交预览请求；服务器重新读取订单和库存并返回最终分配、无订单数量和库存缺口。
6. 没有警告时直接保存；存在警告时显示逐项确认摘要。
7. 用户确认后提交带预览版本标识的保存请求。服务器再次计算；若结果与预览不同，则不保存并返回更新后的警告。
8. 结果未变化时，以单一事务保存整个批次。

如果客户下没有组装配置、组装图号没有有效配件、产品已删除或实际数量非法，系统阻止保存并显示具体原因。

## 历史展示、修改与删除

组装发货批次显示在现有已发货页面，与普通发货记录处于同一历史区域，但采用批次卡片或分组行展示：

- 批次头显示客户、组装件图号、套数、发货日期、备注和操作人。
- 配件行显示配件图号、产品名称、单套用量、计算数量、最终数量、匹配订单及无订单数量、库存缺口。
- 无订单 allocation 显示“无订单直接发货”。
- 库存不足明细显示“库存缺口 N”。

修改组装发货时允许调整发货日期、备注及各配件最终数量。服务器先撤销原批次对订单汇总和库存的影响，再基于最新订单与库存重新预览；有新警告时要求确认，最终在单一事务中替换原明细及分配。

删除组装发货批次时，恢复其实际扣减的库存数量、移除对应订单分配、重新计算关联订单的已发汇总，并删除批次图片文件元数据。文件系统图片删除沿用现有安全删除规则。

## 权限与安全

- 查看组装发货沿用 `shipped_view` 权限。
- 创建、修改和删除组装发货沿用 `shipped_manage` 权限。
- 编辑产品组装关系沿用 `product_edit` 权限。
- 服务器不信任浏览器提供的客户归属、计算数量、订单余量、库存余额或警告状态。
- 所有 ID、数量和字符串均在服务器端重新校验。
- 动态 SQL 仅对占位符数量进行拼装，值全部通过参数绑定传递。
- 图片上传沿用现有类型和大小校验。

## 事务与并发

预览不写入数据库。最终保存在一个 SQLite 事务内依次完成：

1. 重新读取组装定义、订单余量和库存余额。
2. 与客户端确认的预览版本进行比较。
3. 写入批次和配件历史快照。
4. 写入订单 allocation。
5. 写入库存事务并更新余额，库存最低为零。
6. 同步关联订单的发货汇总。
7. 写入图片元数据。

任一步骤失败均回滚数据库修改。图片文件采用先验证、临时保存、事务成功后落位的现有安全模式；事务失败时清理本次临时文件。

## 错误与提示文案

核心提示包括：

- “该客户没有可用的组装件配置”。
- “该组装件没有有效配件”。
- “组装件套数必须为大于 0 的整数”。
- “配件实际发货数量必须为大于 0 的整数”。
- “配件 {图号}：{数量} 个没有可匹配订单，将作为直接发货保存”。
- “配件 {图号}：库存不足 {数量} 个，确认后库存将扣到 0”。
- “订单或库存状态已变化，请按最新结果重新确认”。

警告不阻止用户继续，但结构或数值校验错误必须阻止保存。

## 测试策略

### 数据层

- 新数据库与已有数据库均可幂等创建新表和索引。
- 产品删除时组装关系级联删除。
- 同一产品重复组装图号被拒绝。
- 客户修改后，组装关系查询自动归属新客户。

### 配置行为

- 一个产品保存多个组装关系。
- 多个产品属于同一组装图号。
- 空行忽略，半空行、零、负数、小数及非数字用量被拒绝。
- 编辑保存能增加、更新和删除关系。

### 展开与匹配

- 套数乘单套用量得到默认数量。
- 人工数量覆盖默认数量但不改变历史计算数量。
- 不同客户的相同组装图号互不串用。
- 多张订单按既定顺序拆分。
- 订单不足的余量生成空 `order_id` allocation。
- 完全无订单时全部数量作为直接发货。

### 库存与事务

- 库存足够时完整扣减。
- 库存不足时扣到零并保存正确缺口。
- 预览后订单或库存变化时要求重新确认。
- 批次中任意写入失败时，批次、订单、库存和图片元数据全部回滚。
- 修改和删除批次能正确恢复并重新应用订单及库存影响。

### 界面与回归

- 产品编辑页显示、增加和删除多行组装关系。
- 客户选择正确过滤组装图号。
- 套数变化即时更新默认数量。
- 警告摘要列出具体配件和数量。
- 组装批次在已发货历史中正确分组展示。
- 现有普通订单发货、编辑、删除、库存同步、图片上传和导出测试继续通过。

## 验收标准

以下场景必须完整通过：客户 A 的组装件 `ASM-100` 包含配件 P1 每套 2 个、P2 每套 3 个。输入 100 套后页面默认显示 P1 为 200、P2 为 300，并允许将 P2 改为 280。P1 有两张未发订单时按规则拆分；P2 没有订单时提示并作为直接发货。若 P2 库存只有 250，页面提示缺口 30；用户确认后保存 280 个发货数量、扣减 250 个库存、库存余额为 0，并在历史记录中保留无订单和缺口信息。整个批次的任一写入失败时不留下部分记录。
